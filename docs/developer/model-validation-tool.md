# Synthetic model implementation QA and data readiness

The `crm_validate_model` action is limited to synthetic statistical implementation QA and structural historical-data readiness. It is not an election model. It never fits actual election outcomes, calculates party or candidate probabilities, forecasts elections, or scores or ranks political participants. All reports set `experimental: true`, `publicationEligible: false`, and `electionForecastingSupported: false`.

The fixed synthetic QA uses a normal-inverse-gamma model only on generated, nonpolitical normal observations. Its simulation-based calibration (SBC) diagnostics retain posterior ranks for both the location (`mu`) and variance parameters, use deterministic bounded seeds, and verify independently generated posterior draws. These diagnostics are implementation checks, not a statistical-readiness certification or a pass/fail finding. Stan describes SBC as simulating parameters and data from a joint model and checking posterior-rank behavior ([Stan User’s Guide](https://mc-stan.org/docs/2_39/stan-users-guide/simulation-based-calibration.html)).

For a required one-to-five-state request, the fixed runner reads only `.etl/staging/<state>-2024-staging.json` and `data/canonical-jurisdictions.json`. It reports structural counts: artifact identity hash, canonical county-tag recognition, state/tag consistency, safe nonnegative `totalVotes` integer presence, source IDs, and whether a source digest is separately reviewed. It does not inspect vote components, calculate shares, fit observations, or report actual election outcomes. An absent staging artifact or missing declared reviewed digest is inconclusive, never certification.

The action accepts only `states`, optional bounded integer `seed`, and the exact confirmation `VALIDATE_EXPERIMENTAL_MODEL`. Its TypeScript runner invokes a fixed Python argv array with no user-supplied path, code, URL, model, target, environment, or output directory. It produces only normal MCP audited-run evidence under `.etl/mcp-runs`; it cannot publish, promote, or mutate a database.

For reproducibility each output hashes the structured fixed specification together with the executing implementation bytes, and records the implementation hash independently. Staging artifact hashes are reported separately. Those identities establish what was inspected, not source certification.
